Hướng Dẫn Sử Dụng Cho Chủ Đầu Tư

Trang quản trị (Owner) admin/owner.html dành cho ban quản lý dự án, đội marketing và đội kỹ thuật. Cho phép chỉnh sửa toàn bộ nội dung trang VR, xem báo cáo, quản lý người dùng và xem leads.

Giới Thiệu Vai Trò

Hệ thống có 3 vai trò:

RoleTài Khoản DemoQuyền
developerdev / dev@2025Toàn quyền + xem/sửa tab API (key, webhook)
owneradmin / aurora@2025Toàn quyền nội dung + user, KHÔNG sửa được tab API và không gán được role developer
salessales / sales@2025Workspace riêng (sales.html) — xem HDSD Sales

Với tư cách Owner (hoặc Developer), bạn có quyền:

  • Quản lý kho Bất động sản (căn hộ, shophouse, penthouse, duplex…) — CRUD đầy đủ.
  • Chỉnh mọi nội dung trên trang VR: thư viện media, tài liệu, tiến độ, danh sách VR (nav panel), masterplan, pháp lý, vị trí + POI.
  • Đổi theme (9 biến màu + 5 preset + 6 toggle hiệu ứng) — lưu vào DB và áp dụng cho trang public.
  • Quản lý bản dịch i18n: inline edit, thêm/xoá ngôn ngữ.
  • Xem Analytics theo lượt xem, scene, voice AI, funnel, leads — số liệu thật từ DB.
  • Quản lý người dùng (tạo/sửa/xoá tài khoản sales, đổi mật khẩu).
  • Backup / Restore qua Export / Import JSON, Reset về mặc định.
Khác biệt lớn so với phiên bản cũ Hệ thống đã chuyển sang backend MySQL + JWT-like session token. Khi bạn bấm Lưu trong admin, dữ liệu được ghi thẳng vào DB và trang public lập tức đọc được qua GET /api/project — không còn quy trình "export JSON rồi upload thủ công" như trước.

Stack

  • Backend: Node.js + Express 4.21, MySQL 2 driver, Bcrypt + SHA-256 session token (TTL 12h).
  • Storage media: Cloudflare R2 (S3-compatible) — upload qua presigned URL.
  • Frontend admin: HTML/CSS/JS thuần (không framework), Chart.js cho biểu đồ, Leaflet cho Masterplan.
  • Frontend public VR: iframe 3DVista + Gemini Live WebSocket.
Khởi động server Trong thư mục server/: npm install rồi npm start. Cần biến môi trường DATABASE_URL (hoặc DB_HOST/PORT/USER/PASSWORD/NAME) và R2_* nếu dùng upload ảnh.

Đăng Nhập

1
Mở trang đăng nhập
Truy cập admin/index.html. Trang login có UI tối giản với gợi ý 3 tài khoản demo.
2
Nhập thông tin
Tài khoản Owner: admin / aurora@2025.
Tài khoản Developer (mọi quyền): dev / dev@2025.
3
Bấm "Đăng Nhập"
Frontend gửi POST /api/auth/login. Backend trả về { token, user }; token lưu trong sessionStorage key ah_session. Sau đó chuyển trang theo role: owner/developer → owner.html; sales → sales.html.

Đăng Xuất

Bấm "Đăng xuất" trên topbar. Gọi POST /api/auth/logout, xoá session khỏi DB và xoá ah_session khỏi sessionStorage, chuyển về trang login.

Auto-Redirect Nếu Đã Login

Khi mở admin/index.html, nếu sessionStorage có token, frontend gọi GET /api/auth/me. Nếu token còn hợp lệ → chuyển thẳng tới home tương ứng. Nếu token hết hạn → xoá session, ở lại trang login.

Bảo mật Tài khoản admin có quyền chỉnh sửa mọi dữ liệu dự án và quản lý user. Tuyệt đối không chia sẻ mật khẩu. Khi triển khai production:
  • Đổi mật khẩu mặc định ngay (qua tab Settings → Users).
  • Đặt biến môi trường JWT_SECRET / AUTH_TOKEN_TTL_HOURS riêng.
  • Bật HTTPS — token gửi qua header Authorization: Bearer <token>.

Pattern Lưu Dữ Liệu

Phần lớn module dùng pattern "sửa local rồi push toàn bộ project":

  1. Frontend duy trì state S.data trong bộ nhớ (cache localStorage.ah_admin_data).
  2. Mọi thay đổi cập nhật S.data ngay.
  3. Khi bấm Lưu → gọi PUT /api/project với toàn bộ object JSON → backend ghi vào DB trong transaction.
  4. Riêng phân khu có endpoint nhanh hơn: PUT /api/subdivision/:code.

Hoàn Tác

Hệ thống không có Undo. Cách an toàn:

  • Trước khi chỉnh sửa lớn → vào Cài Đặt → Backup → Export JSON.
  • Nếu lỡ làm hỏng → Import file backup gần nhất → ghi đè DB.

Property Detail (Trang Riêng)

Khi bấm vào 1 BĐS → mở trang p-property-detail với các block:

  • Thông tin cơ bản: mã, tên, phân khu, loại hình, diện tích, số phòng, hướng, giá, status, pháp lý, ngày bàn giao.
  • Hình ảnh sản phẩm: upload (drag-drop hoặc link URL) — lưu lên R2.
  • Mặt bằng (floor plan): upload ảnh riêng cho từng phòng / tầng.
  • Điểm nổi bật (highlights): danh sách bullet (mỗi dòng một item trong textarea).
  • Chính sách bán: chiết khấu, lịch thanh toán, ưu đãi.
  • Tài liệu: link PDF/folder Drive đính kèm.
  • Tiến độ (milestones): mốc bàn giao riêng cho căn này.
  • Gán sales phụ trách: chọn từ danh sách user role=sales → hiển thị contact (phone/zalo/email/facebook).

Sửa Trạng Thái Nhanh

Trên List View, bấm badge trạng thái → xoay vòng giữa available ↔ sold.

Ngôn Ngữ & i18n

Quản lý bản dịch cho 5 ngôn ngữ mặc định (VI, EN, ZH, KO, JA) và có thể thêm ngôn ngữ mới.

Bảng Dịch (Inline Edit)

Dữ liệu nạp từ GET /api/i18n/admin. Hiển thị bảng:

  • Key (vd topbar.gallery).
  • Namespace (nhóm key — topbar · form · overlay…).
  • Gốc (VI) — luôn đọc-only.
  • Dịch sang ngôn ngữ đang chọn — click ô để edit, blur để lưu (PUT /api/i18n/entry).
  • Status: translated / missing.

Lọc

  • Tìm theo key / nội dung.
  • Lọc theo namespace.
  • Lọc theo status (chỉ hiện key chưa dịch).

Thêm / Xoá Ngôn Ngữ

1
Bấm "+ Thêm ngôn ngữ"
Form: mã ngôn ngữ (vd fr) + tên hiển thị (vd "Français") + cờ.
2
Lưu

Upload Ảnh (Cloudflare R2)

Mọi ảnh trong admin đều được upload lên Cloudflare R2 qua presigned URL — không lưu base64 trong DB.

Cơ Chế

1. Frontend chọn file (drag-drop hoặc input)
2. POST /api/upload/presign → backend dùng AWS SDK v3
   tạo presigned PUT URL (TTL 5 phút)
3. Frontend PUT file thẳng lên R2 (không qua backend)
4. URL công khai sau upload:
   https://{R2_PUBLIC_BASE}/{folder}/{timestamp}-{random}.ext
5. Lưu URL công khai vào DB (qua module tương ứng)

Cấu Hình R2 Cần Thiết

  • R2_ACCOUNT_ID — Cloudflare account ID.
  • R2_ACCESS_KEY_ID + R2_SECRET_ACCESS_KEY — credentials.
  • R2_BUCKET — tên bucket.
  • R2_PUBLIC_BASE — URL public của bucket (qua Cloudflare custom domain hoặc pub-*.r2.dev).

Test bằng GET /api/health — endpoint này trả về cả trạng thái R2.

Nếu R2 chưa cấu hình Module upload sẽ hiển thị lỗi "Không thể lấy presigned URL". Bạn vẫn có thể dùng link URL để gắn ảnh ngoài (ImgBB, Cloudinary, v.v.).

FAQ & Xử Lý Sự Cố

Tôi vừa chỉnh thêm 5 căn, trang VR public đã thấy chưa?

Có — backend MySQL nên trang public đọc trực tiếp từ DB qua GET /api/project. Khách refresh trang sẽ thấy ngay. Khác phiên bản cũ cần publish thủ công.

Mở admin trên máy khác thì dữ liệu có khác không?

Không — dữ liệu nằm trên MySQL backend, không còn phụ thuộc localStorage. Đăng nhập ở máy nào cũng thấy cùng một bộ dữ liệu.

Bấm "Lưu" báo lỗi 401 Unauthorized?

Session token hết hạn (TTL 12 giờ). Đăng xuất rồi đăng nhập lại. Nếu vẫn lỗi → check JWT_SECRET trong env có khớp giữa lần login và lần lưu không.

Upload ảnh báo "Không lấy được presigned URL"?

Backend chưa cấu hình R2 hoặc credentials sai. Check GET /api/health để thấy trạng thái R2. Xem mục Upload Ảnh.

Mất mật khẩu admin?

Vào DB (MySQL CLI hoặc phpMyAdmin) → bảng users → cập nhật password_hash bằng bcrypt hash mới. Hoặc chạy script server/src/seed-accounts.js để reset 3 tài khoản demo.

Có giới hạn số lượng căn hộ, hotspot, POI không?

Backend MySQL không giới hạn — có thể chứa hàng nghìn căn. Hiệu năng UI bắt đầu giảm khi vượt ~500 căn trên 1 trang list (nên dùng filter/pagination thay vì load all).

Slide Panel không đóng được, kẹt giữa màn?

Bấm × hoặc nhấn Esc. Nếu vẫn kẹt, refresh trang F5. Dữ liệu chưa lưu sẽ mất — bấm Lưu ngay sau khi thay đổi.

Có log thao tác (audit log) không?

Có bảng analytics_events ghi nhận một số hoạt động chính. Audit log chi tiết per-user (ai đổi gì lúc nào) là roadmap tương lai — hiện chưa.

Backend không khởi động được?

Check theo thứ tự: (1) DATABASE_URL hoặc DB_* — MySQL có chạy không? (2) Chạy node server/src/migrate-auth.js rồi seed.js để tạo bảng + dữ liệu mẫu. (3) Port 3000 có bị chiếm không — đổi qua biến PORT.
